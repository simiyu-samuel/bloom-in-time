# Competition release checklist

All application/release items are intentionally unchecked. A documentation baseline is not a completed submission.

## Account and content

- [ ] Owner confirms Start membership is active, not merely an application submitted.
- [ ] Developer Access and entry eligibility are confirmed privately.
- [ ] Gaming / New Experience is selected and dated development records are retained.
- [ ] Every used asset has a checked source/license/attribution record.
- [ ] English UI, instructions, captions, and submission materials are complete.
- [ ] Applicable Meta policies and content restrictions are checked against actual content.

## Playable build

- [ ] Clean install, typecheck, meaningful tests, and production build pass.
- [ ] Every shipped level validates and has a checked solution.
- [ ] Start, play, hints, undo, reset, pause, next, replay, settings, and exit work through emulated hands.
- [ ] One-hand use, sound-off play, reduced motion, and contrast are checked.
- [ ] Tracking loss, tab hiding, XR rejection, and session exit recover.
- [ ] Save/reload and storage failure behave safely.
- [ ] Performance evidence names the actual environment; no unmeasured Quest claim appears.
- [ ] No critical known failure blocks completion.

## Hosting and materials

- [ ] Public HTTPS URL works without login/payment and all assets load.
- [ ] Fresh-session browser and emulated XR entry are checked at the final URL.
- [ ] Actual gameplay video is under three minutes and public on YouTube/Vimeo.
- [ ] Video identifies emulation and demonstrates the shipped experience.
- [ ] Screenshots and text match available features.
- [ ] Tagline is at most 140 characters; description stays within suggested 500 words.
- [ ] Owner supplies private participant details and confirms launch plans.
- [ ] Form includes working project/video links and correct track/division.

## Final state

- [ ] Record final commit SHA, build command, package versions, URL, and evidence.
- [ ] Verify the deployed commit and annotate the competition-final tag.
- [ ] Submit before November 18, 2026 at 23:00 Africa/Nairobi; preferably November 17.
- [ ] Confirm Devpost received the complete entry and retain confirmation privately.
- [ ] Disable automatic updates to the submitted URL at the deadline.
- [ ] Preserve the unchanged build and public materials through winner announcement.
- [ ] Continue later work only at a separate preview URL/branch.

Physical Quest testing is unavailable. Leave any hardware-validation claim unmade; the final application must still be built for the judged devices.
