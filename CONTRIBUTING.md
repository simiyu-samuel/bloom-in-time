# Working on Bloom in Time

This is currently a solo project. These conventions support clear history and future collaboration.

1. Read [repository instructions](AGENTS.md) and [current status](docs/planning/status.md).
2. Select the next ready item in the [backlog](docs/planning/backlog.md).
3. Implement a bounded change, including meaningful verification.
4. Update relevant design decisions and mark only completed work as done.
5. Review the diff and commit a coherent result.

Use main for the documentation baseline. Future implementation may use short-lived feature branches. Commit subjects should describe the change: docs: define pulse timing, feat: add snapped placement, or fix: cancel a grab on session loss.

Do not put personal verification documents, private contact details, credentials, or unpublished video captures into Git. Submit private registration information through the relevant platform.

A public repository, remote hosting account, and source license have not been chosen. Local commits do not create a remote repository or publish the project.
